1. Getting started

StemSplitter is portable, so there is nothing to install. Extract the folder anywhere (a USB drive works too) and run StemSplitter.exe. Python is not needed.

The first time you use a model, the app downloads it into the models folder. After that it works offline. To download every model in advance, use ⟳ Models → ⬇ Download missing.

The ☀ Light / ☾ Dark button in the top right switches the theme. The ? Help button opens this guide.

3. Separating songs step by step

  1. Input: drag audio files or whole folders onto the drop area. You can also click it, or use Add files… / Add folder…. Clear empties the list. Supported formats: MP3, WAV, FLAC, M4A, OGG, AAC, WMA, OPUS, AIFF.
  2. Model: pick one of the three models (see above).
  3. Output: tick the stems you want to keep, then choose the folder, format, quality and device.
  4. Click ＋ Add to queue. Every file becomes a separate job.
  5. Click ▶ Start. Progress shows below the queue. When a job is done, double-click it to open its folder.

4. Output options

SettingMeaning
StemsOnly the ticked stems are saved; the rest are deleted after separation.
FolderWhere results go. Default: the output folder next to the app.
Separate folder per songOn: output\My Song\vocals.wav. Off: output\My Song_vocals.wav.
FormatWAV (lossless, large), FLAC (lossless, smaller) or MP3 (320 kbps).
QualityFast / Normal / Best. Higher quality takes proportionally longer. For Demucs it sets the number of “shifts” (1 / 2 / 5). For RoFormer it sets the overlap (2 / 4 / 8). Best is about 2–3× slower than Normal and the difference is small. Normal is a good default.
DeviceAuto (GPU if available) uses an NVIDIA GPU if it works, otherwise the CPU. CPU only always uses the processor. See CPU vs. GPU build.

Settings are remembered between sessions. Each job keeps the settings it was added with, so changing them later does not affect jobs already in the queue.

5. The job queue

Jobs run one at a time, in order. Each job runs in its own process, so it can be stopped at any moment.

ControlWhat it does
▶ StartStarts processing the waiting jobs.
⏸ Pause after currentLets the running job finish, then stops the queue.
■ Stop currentKills the running job immediately (status: Stopped).
Resume on launchWhen on, waiting jobs start automatically the next time the app opens.
↻ RetryPuts the selected finished, failed or stopped jobs back to Waiting, e.g. to run them again.
▲ ▼Move the selected job up or down in the queue.
✕ RemoveRemoves the selected jobs (or press Delete).
Clear finishedRemoves all done, failed and stopped jobs from the list.
📁 Open outputOpens the selected job's result folder (or double-click the job). With nothing selected, it opens the output folder.

Job statuses: ○ Waiting, ▶ Running, ✔ Done, ✖ Failed, ■ Stopped. While a job runs, the Info column shows its phase and progress. Afterwards it shows the number of stems, the run time and the device used (CPU or the GPU's name). Select a job to see its detailed log in the Log panel at the bottom. The queue is saved and is still there after you close and reopen the app.

6. Model manager

⟳ Models lists the three models with their download status, size and date.

  • ⬇ Download missing: downloads every model that is not on disk yet. Use it before going offline.
  • ⟳ Re-download selected: downloads the selected models again, to update or repair them. The old file is kept until the new one has arrived, so a failed download doesn't leave you without a model.
  • 📁 Folder: opens the models folder.

Downloads also run as queue jobs. They are placed in front of the waiting separation jobs, and their progress shows in the queue.

7. CPU build vs. GPU build

There are two builds of StemSplitter. Both use exactly the same three models and the same program code. They differ only in the computing libraries bundled with them:

CPU build (StemSplitter)GPU build (StemSplitter-GPU)
PyTorch2.8.0, CPU-only2.8.0 with CUDA 12.8 (CUDA/cuDNN libraries included)
ONNX Runtimeonnxruntimeonnxruntime-gpu
Size~0.9 GB~5 GB (almost all of the difference is the CUDA libraries)
HardwareAny 64-bit Windows 10/11 PCNVIDIA GPU, GTX 900 series or newer, driver 570 or newer
Uses the GPUNeverAutomatically, when a usable card is found

How the GPU build picks the device

At the start of every job, the GPU build runs a small test calculation on the graphics card. If it works, the job runs on the GPU and the Info column shows the card's name. If it fails, the job runs on the CPU exactly like the CPU build does. This happens with no NVIDIA card, an outdated driver, or a card too old for current PyTorch (for example a GT 710). Choosing CPU only forces the CPU in either build.

What this means in practice

  • Speed: on a modern NVIDIA card (e.g. RTX series) separation is roughly 10–50× faster. A song takes well under a minute, compared with several minutes on a CPU.
  • Result: the same model with the same settings gives practically the same output in both builds. Tiny floating-point differences are possible but not audible.
  • Models: you can copy the models folder between the two builds, so nothing needs to be downloaded again.
  • Which one to use: without an NVIDIA card, use the CPU build. It is smaller and does the same job.
The GPU build is too large for GitHub releases. You can create it from the source code with build.bat gpu.

8. Files and folders

Everything is stored next to StemSplitter.exe, so you can copy or move the whole folder:

StemSplitter\
├── StemSplitter.exe
├── models\          downloaded model files
├── output\          default result folder
├── ffmpeg\          audio decoder/encoder
├── jobs.json        the saved queue
└── settings.json    your settings

To start over, delete jobs.json and settings.json. Delete the models folder to free disk space; the models are downloaded again when needed.

9. Troubleshooting

ProblemSolution
Separation is very slowThat is normal on a CPU: a song can take several minutes per model, and longer at Best. Use Fast or Normal, or the GPU build with an NVIDIA card.
The GPU build uses the CPUCheck the job's log. It says why the GPU wasn't used (no CUDA GPU, card not supported, …). Update the NVIDIA driver to version 570 or newer.
A model download failsCheck the internet connection and try ⟳ Models → ⬇ Download missing again. A firewall or proxy may block the download.
A job failedSelect it and read the last lines of the log. Common causes: a damaged or unsupported input file, or not enough disk space or memory. Fix the cause and press ↻ Retry.
Drag & drop does not workUse Add files… / Add folder…. Windows also blocks drag & drop between programs running as administrator and normal programs.
The app won't startMake sure the whole folder was extracted (don't run the exe from inside the zip), and that your antivirus did not quarantine any files.
